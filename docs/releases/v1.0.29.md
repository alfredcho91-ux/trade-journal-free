# Trade Journal v1.0.29 — Windows app window and Strategy Discovery

Windows x64 **limited-beta prerelease**. The existing **release hold remains**:
clean-machine Windows acceptance and live read-only Deepcoin/Binance smoke tests
are still required before broader distribution. This release does not add order,
withdrawal or asset-transfer capabilities.

## Changes since v1.0.28

- Windows now opens a dedicated Trade Journal window using Edge WebView2 instead
  of a Chrome/default-browser tab. X, Alt+F4 and the power button share a guarded
  close path that protects active saves and dirty forms and stops the parent and
  sample servers. Duplicate launches restore the existing profile's window.
- Sample workspaces remain isolated, offline Python child processes and open
  inside the same app window. Existing DB and credential-vault paths are retained.
  External links open in the default browser. The page bridge exposes only close.
- Strategy Discovery MVP adds `/strategy-discovery`: explicit analysis of recorded
  closed positions, a chronological 70% discovery / 30% holdout split, immutable
  candidate evidence, and explicit review/registration in Playbook. Candidate rules
  cover recorded symbol/direction conditions; they do not generate risk/exit rules,
  guarantee returns, execute trades or call an external AI service.
- Discovery uses additive local SQLite schemas. Existing strategy versions remain
  readable, including descriptive-only v2 definitions and evaluator-bearing clones.
- README, architecture, Windows KO/EN guides and version declarations are updated.
  Windows packaging checks command failures and generated-output boundaries;
  automatic release publication explicitly preserves prerelease status.

## Download and run

Download `Trade-Journal-Windows.zip`, extract it completely and run
`Trade Journal/Trade Journal.exe`. Keep the complete `_internal` directory next to
the EXE. Python and Chrome are not required. **Microsoft Edge WebView2 Runtime is
required**; install the Evergreen Runtime from
[Microsoft](https://developer.microsoft.com/microsoft-edge/webview2/) if missing.
No runtime installer, updater or macOS native-window build is included.

The current local build is unsigned; release signing is not certified here.
An unsigned build may show SmartScreen warnings. Do not disable Windows protection.

## Validation and limitations

Local implementation validation on 2026-10-31:

- Frontend: 50 files / 505 tests passed; lint, TypeScript and production build passed.
  Under local memory pressure the full passing run used one thread worker without
  changing assertions or timeouts.
- Backend: release-preparation full suite 1,109 passed / 1 optional TA-Lib
  comparison skipped / 215 existing dependency warnings, including all 19 desktop
  tests. The release commit also runs the full CI suites and mandatory
  TA-Lib regression job before Windows packaging.
- Core/route/Plan Lab isolation and version guards, diff review and ZIP content
  inspection passed. The local ZIP contained no user DB, environment file, private
  API key or log; the public certifi CA bundle is intentional.
- Source and packaged Windows checks passed: first run, same-window sample
  transition, duplicate launch, dirty daily-journal close/cancel, sample power-button
  shutdown, report open/Escape, native window close, process/port cleanup, restart
  from the final folder and persisted normal-workspace language settings.

Clean Windows user/VM acceptance, a missing-WebView2 machine, live exchange sync,
real credential/persistence acceptance and live price charts remain unverified.
Sample checks do not substitute for these. Native accessibility snapshots did not
reliably identify the focused web element after Tab; detailed focus behavior is
covered by frontend tests. Prior actual 200% browser zoom, report reopening from
the same sample URL and mixed KO/EN Risk wording remain follow-ups.
